- **glincker/ableton-skills** (MIT, organisation Glincker, no individual author named). Twelve
  prompt skills for Ableton Live 11+. Needs a separate Ableton MCP server
  (`uisato/ableton-mcp-extended` or `ahujasid/ableton-mcp`) talking to a running copy of Live.
- **wstierhout/ableton-live-mcp** (MIT, Wouter Stierhout). An MCP server with 156 tools over a
  Live Remote Script (socket 127.0.0.1:9877). Needs Live 11 or 12 running. Its own README says
  Live's API has no render or freeze, so exporting is manual; offline tools edit `.als` files but
  render no audio.
- **Korben00/ableton-producer-skills** (MIT, Korben). Claude Code skills on the beta Live 12
  Extension SDK. Needs Live 12 (Suite recommended) with Developer Mode, which resets on every
  restart.

All three Ableton options need a licensed, running Ableton Live and cannot render headless.
Ableton Live is not installed and no licence is known, so none was installed.

## Decision

A headless toolchain written for this project: a numpy/scipy synthesis engine (band-limited
oscillators, Karplus-Strong strings, FM, modal percussion, time-varying filters, tape and space
effects), a rule-based sequencer, a mixer and master chain, a standard MIDI file writer and an
analysis suite. ffmpeg's `ebur128` filter cross-checks the loudness. Every sound is generated by
code, so there are no third-party samples to license. Reasons: it renders unattended and
reproducibly from a seed; every decision is inspectable code; it needs no licence and no
install.

## What "listening" means here

I (Claude Opus 5.5) cannot hear audio, and no audio-capable model is wired into this session.
Every judgement in the diary comes from numerical analysis, plots I looked at (spectrograms,
loudness curves, bar-by-bar self-similarity, onset-position histograms) and reading the score
data. None of it comes from listening. Jonathan's ears are the real test.
